# MoonLabeler 中文使用说明

作者：**Fluorine Zhu** · **GPL-3.0-or-later** · [English / 项目主页](README.md)

在自己的月面照片上配准地形、编辑名称并导出标注。采用 Python / Qt，支持局部月面和镜像照片。

## 从源码打开

```bash
git clone https://github.com/Fluorine7/MoonLabeler.git
cd MoonLabeler
./start-mac.command
```

也可双击 `start-mac.command`。首次运行会创建虚拟环境并安装依赖。当前交付为源码，没有打包。

启动窗口自动最大化，铺满当前屏幕可用区域。macOS 的标注设置控件填满表单右侧列，语言下拉菜单可完整显示“双语 / 英文 / 中文”。

照片画布位于左侧，检查器位于右侧。侧栏分为“校准”“标注”“参考”三个工作页。“校准”下的“辅助找坑与参考点”默认折叠，展开后按检测候选、选择名称、确认参考点、配准的顺序操作；没有独立的“手动补点”页签。无法找到合适候选时，可展开“手动补点”。打开新照片自动回到“校准”、收起辅助内容，保留当前日期和时间；加载工程保留工程时间。

## 自动识别并标注

1. 打开照片，核对拍摄日期；年、月、日分别输入，输入满位后跳到下一框。启动默认 UTC 15:00；打开新照片时，WinJUPOS 格式文件名自动填入 UTC，其他文件保留当前时间。“具体时间”默认折叠，展开后时、分分别输入，小时输入满位后跳到分钟；秒保留文件名导入值、旧工程值或默认 0。收起和更换日期保留已选时间，恢复默认按钮可重置到 15:00。北京时间需换算为 UTC，注意跨天。地点可选；不填使用地心视角。旧工程加载时保留原始精确时间。默认时间便于操作，不能保证极区高倍照片的精确投影。
2. 直接点击 **“自动识别并标注”**。无需先点“计算月面几何”，也无需输入区域、地名、比例、旋转或镜像状态。
3. 成功后会跳到“标注”页。纹理配准显示图像对应点数量；坑群配准显示匹配地名，并将这些地形加入“校准 → 地形点”。标签由已配准的月面目录投影得到，并非逐个从照片检测。整月盘优先显示命名环形山和月海，避免长月溪挤掉主要环形山。
4. 拖动文字调整位置，保存工程，导出 PNG / SVG。无法通过验证时不会采用猜测地名，也不会覆盖已有配准。

识别先将内置 **LROC 反照率纹理**投影到 JPL 当前视角，进行双向 SIFT 特征匹配与 RANSAC 相似变换验证。月海对比明显、坑缘很淡的整月盘可走这条路径；要求至少 24 个图像对应点、45% 内点共识、分散覆盖和月盘范围一致。图像对应点不被当作已命名环形山。

纹理配准之后，会尝试用分散的对应点精修整体投影，按实际月面范围作分区留出验证，避免照片的大黑边影响覆盖率判断。能测得较完整外缘时，还独立检查投影月盘的中心和比例；只有纹理分区和月缘验证同时通过才采用较大的观测方向微调。月缘不一致的结果拒绝采用，不把引线强行挪到月缘。原始星历视角和验证结果保存在工程中；该拟合修正不是实测天平动或反推出的拍摄地点。旧配准需重新点击“自动识别并标注”；“重新生成标注”只更新文字和布局。

纹理特征匹配失败后，先尝试较完整月盘外缘的圆拟合：要求至少 120° 弧段，同时验证月相、去除大尺度明暗变化后的 LROC 纹理以及竞争旋转 / 镜像方向。该路线不把外缘采样点当作已命名的坑中心。界面中的拟合偏差只描述月盘外缘，不是每个标签的定位误差。

随后使用 **OpenCV EDCircles** 合并不完整坑缘，并在当前视角下的 USGS / IAU 目录中搜索三坑图案，用其他坑验证区域。先搜索独立命名坑；失败后扩展到多尺度卫星坑目录，并检索照片中二十个最大候选的关系。扩展搜索至少需要七个大候选对应点，不能用很多小纹理碎片凑出共识。两条坑群路径均检查覆盖范围、月盘范围和竞争区域。阴影造成的重复候选仍可能出现；不会给它们自动重复分配同一地名。这些条件是工程启发式，不是正确率保证，也不是轨道相机的完整椭圆投影不变量。

以上方法失败后，用 **LOLA LDEM_16** 生成全月坡度与地形阴影参考，分块搜索旋转和镜像。至少 24 个图像对应点、分布覆盖、密集明暗及细节相关和竞争区域检查共同验证；不会把纹理点当成命名坑。明暗相关通常要求至少 0.60；0.59–0.60 的窄边界只在至少 32 个对应点、15% 覆盖和至少 0.30 细节相关时接受，其他拒绝条件不变。

极区斜视照片中，粗略球面参考可能已找到正确区域，却因地形高度和观测方向的偏差无法对齐。候选可进入含高程的局部精修；仅有 12–17 个粗匹配点时，还要求至少 15% 覆盖、0.60 明暗相关与 0.35 细节相关，且不能直接作为识别结果。必须重新取得足够分散的对应点，通过空间分区留出验证及重新渲染检查。重叠分块的同一结果只精修一次，最多检查两个不同区域。

若精修后的整幅明暗相关仍低于 0.60，只有在至少 80 个对应点、25% 覆盖、0.50 明暗与细节相关、至少四个验证区域、留出误差不超过 1.5 px 且至少改善 25% 和 0.5 px 等条件同时满足时才接受。这是受限的几何与细节联合检查，并非放宽全部照片的识别门槛；像素误差按计算图尺寸计，不代表每个地名的绝对精度。2020-08-06 Endymion 与 2004-09-03 Gärtner 实拍已通过无参考点的本地回归。

每轮分块搜索只提取一次照片特征；阴影计算跳过已遮挡、或已高于 DEM 最高点且继续向外的射线，保留原采样结果。不新增模型或大型数据库。

参考点辅助搜索也保留这些候选，在高程精修后再次检查全部已确认点。已有粗匹配通过时，不会因此跳过其他区域中有竞争力的候选；仍不能区分的结果拒绝采用。

坑群识别成功后也会使用同一份小 DEM 精修。局部参考图通过视线与高程表面相交采样，拟合采用同一地形高度，避免把坑壁高差混成观测方向误差。先验证小范围相机修正，再重新取得分散的地形对应点，尝试两个观测方向参数与相机比例/旋转/平移的联合微调。高程后备匹配可使用相同的含高程投影精修。按 3×3 空间分区留出验证，至少四个区域可检查、加权留出误差明显改善，且重新渲染的整幅明暗和细节相关通过后才采用；否则保留原配准。通过含高程精修的结果也可生成高程坑缘并拟合平滑椭圆。微调记录及原始星历视角保存到工程，不推定摄影地点，也不将图像拟合值称为天平动测量。

纹理参考图约 550 KB，随源码提供，来源及 JPEG 重压缩记录见 `moonlabeler/data/moon_albedo_2k.provenance.json`。运行自动识别无需访问 NASA SVS 图片服务器或下载 AI 权重。首次需要约 20 MB JPL 星历；高程后备匹配另需约 33 MB LOLA LDEM_16，缓存后可离线识别。OpenCV 依赖使用含 `ximgproc` 的 `opencv-contrib-python-headless`，启动脚本会迁移旧依赖。

已在若干独立实拍照片上做过本地回归，但成功样本不代表其他区域、月相和清晰度的识别率。摄影师的照片及其导出图仅用于本地测试，不随源码发布。极区、月缘、强阴影和过少可靠坑缘仍可能导致拒绝；失败会保留已有配准。

## 疑似坑中心检测

1. 打开局部月面照片，展开“校准 → 辅助找坑与参考点”。检测本身无需拍摄时间、地点或联网。
2. 可直接使用默认参数检测，也可展开“检测设置”，调整最小、最大半径（**原图像素**，椭圆取长短半轴平均值）、灵敏度及候选上限，再点击“检测疑似坑中心”。灵敏度越高，候选通常越多，误检也可能增多。
3. 若照片很大或带水印，先放大到感兴趣的区域，勾选“只检测当前视野”。检测计算最长边限制为 1600 像素；局部视野有助于保留小坑细节。区域边缘不完整的坑可能被排除。
4. 点击照片上的十字或列表行，查看选中的拟合坑缘。默认只显示选中轮廓，避免大量圈线遮住照片；也可勾选“显示全部候选轮廓”。
5. 若中心偏向阴影边缘，点击“重选中心”，再点照片中真实的坑中心。手动修正后不再显示原拟合轮廓。切换工作页会取消待选操作。
6. 在滚动页内搜索环形山名称，点击结果列表中的地名，再点击“确认地名，加入参考点”。单条结果（如 Hadley C）也直接列出；输入名称后不会自动指定地名，按 Enter 可选中首条结果。这里仅列环形山，月溪、山脉等可在“手动补点”中搜索。已有同名参考点会被更新。可以继续确认其他候选。
7. 点击“查看参考点”，在同一页展开“参考点与配准”。只有一两个确认点时，可点击“用参考点自动配准”；至少三处分散、不共线的参考点确认后，也可点击“按参考点手动校准”。已确认的点随工程保存。候选本身不写入工程；换照片或打开工程会清空候选，检测参数会随工程保存。

可移除误检候选，或导出 CSV 供比较。CSV 坐标以原图左上角为原点，x 向右、y 向下；输出半轴、方向、检测方法与边缘支持度。支持度用于候选排序，**不是识别正确率或定位精度**；手动中心的支持度留空。

这个人工辅助检测改编自 Ram Maruboina 的 Lunar Crater Detector，使用 OpenCV / NumPy。它寻找疑似圆形/椭圆坑缘，山脊、阴影和水印可能误检，强阴影或残缺坑缘可能漏检或导致中心偏差。该按钮仅输出候选；自动名称识别使用顶部独立的“自动识别并标注”。

## 参考点辅助自动配准

在“手动补点”中自行取点，或在“辅助找坑”中确认候选的名称和位置后，不必凑齐三个点才能尝试自动配准。

1. 确认一两个已知点。以哈德利溪附近的照片为例，可先确认 **Hadley C** 的坑中心；月溪的目录中心不要当成附近环形山的中心。
2. 在“参考点与配准”中点击 **“用参考点自动配准”**。顶部“自动识别并标注”也会优先使用已确认的点。被停用的点和此前自动产生的点不用于引导搜索。
3. 程序搜索参考点附近的地形，自动验证方向、比例和镜像，通过后切到标注页。参考点表显示已确认点与结果的偏差；搜索记录随工程保存。

这一过程复用约 33 MB 的小型 LOLA 高程数据，不需要额外的大型图像数据库。已知点缩小区域，两个点间距或附近检测到的坑半径提供尺度线索；仅尝试少量尺度，通过后立即停止搜索。局部参考匹配默认使用 600 像素边长，避免将基础高程数据过度放大而损失与实拍纹理的对应关系。结果仍需至少 24 个图像对应点、分布覆盖、明暗和细节相关，并与全部已确认点一致。一个点本身不能确定方向和比例。标错地名、误点中心或照片纹理不足仍可能失败；失败保留参考点和原配准，可核对取点或再确认一处地形。

## 手动校准：局部与整月照片

1. 打开照片，选择拍摄日期，启动默认 UTC 15:00，打开新照片时优先识别 WinJUPOS 文件名中的 UTC，未匹配时保留当前日期和时间。准确校准建议勾选拍摄地点，北纬、东经为正。不填地点使用地心近似。
2. 展开“校准 → 辅助找坑与参考点 → 手动补点”。**参考点就是一个已知地名和它在照片中的位置**，不是让程序猜地名。先搜索你认得的环形山，在搜索结果中选中它。
3. 点击“在照片中标记：地名”，再到照片中点击**同一个坑的完整坑缘中心**；不要点亮斑或阴影中心。可以先滚轮放大。每次点击后会退出取点并更新计数，按 Esc 或取消按钮可退出而不添加。换另一个地名重复，添加 3–6 个分散、不共线的点。
4. 在“参考点与配准”中点击“按参考点手动校准”。程序自动计算月面几何并切到标注页；首次需要约 20 MB JPL 星历，缓存在 `.cache/ephemeris`，之后可离线使用。下载失败时保留已添加的参考点，可以重试。默认三点起步；高级设置中手动指定镜像时允许两点，但无法独立检查误差。
5. 参考点表显示每点拟合偏差，悬停可查看留出该点后的预测偏差（至少四点）。至少五点时，程序可提示明显可疑的单点。它不会自动删除参考点。
6. 取消“使用”勾选可停用参考点；双击该行可重新点击中心。修改后重新配准。
7. 选择地形名称，拖动文字、双击编辑；保存工程，或导出原尺寸 PNG / 可编辑 SVG。

自动标签布局采用候选位置搜索和局部间距优化：在地形周围尝试 16 个方位及多个距离，避开其他标签、地形中心、引线和图片边界。环形山按投影半径留出坑缘区域，文字放在坑外，避免压住主坑细节。引线连接标签最近的边缘，不穿过文字。命名地形优先于附属字母坑。

“标注”页中的直径、类别、数量、语言、字号、颜色、受光筛选及坑缘轮廓设置，均在点击 **“重新生成标注”** 后统一应用，调整控件时不重算布局。未应用的设置有明确提示，导出仍使用当前画面。重新生成保留手动拖动的位置；“重新自动排布标签”应用设置并清除手动位置，保留文字和显示选择。

着陆点是独立的可选图层，默认关闭。在“筛选与数量”勾选 **“着陆点（阿波罗 / 嫦娥）”** 后，点击“重新生成标注”。默认浅青色 `#79d9ef`，可通过旁边“颜色”单独设置；使用小档字号、十字和短引线，不画坑缘圈。支持阿波罗 11、12、14、15、16、17 与嫦娥三、四、五、六号。着陆点不受地形类别和最小直径限制，仍遵循照片范围、可见半球、受光筛选、数量上限及避让；背面的嫦娥四号、六号不会出现在地球视角的正面月盘。

数据随程序提供，可离线使用，切换图层不重跑配准。它标记公开坐标对应的地理位置，并非从照片辨认着陆器，精度仍取决于当前配准。设置与标签编辑保存在工程中，PNG / SVG 与画面一致。[坐标来源：NASA NSSDCA / LROC](https://nssdc.gsfc.nasa.gov/planetary/lunar/lunar_artifact_impacts.html)。

新照片的默认标注颜色为近白色 `#f5f5f2`，文字保留深色描边；引线和坑缘轮廓同色。旧工程保留已保存的自定义颜色与字号。

字号按照片短边计算，并按目标的**投影视直径**分大、中、小三档，默认 **1.8% / 1.5% / 1.2%**。“字号（短边比例）”设置最大字号，“字号递减”设置每档减少的百分点，默认 **0.3**；例如最大 1.8%、递减 0.3，三档就是 1.8%、1.5%、1.2%。递减设为 **0** 时统一字号。旁边显示三档比例和原图像素：3811×4864 照片约 69 / 57 / 46 px，6512×8412 照片约 117 / 98 / 78 px。最低字号为 6 原图像素。

分档以投影后的等面积视直径为依据：至少短边 **2%** 为大，**0.8%–2%** 为中，其余为小，考虑月缘压缩、观测距离和配准缩放；同一张图改变地形筛选或数量不会改变已有目标的档位。山脉、月溪等使用目录长度估算尺度，继续用短引线。分档批量计算，不重新读取 DEM 或识别地形。布局避让按每个标签的实际字号计算，画布、PNG、SVG 一致，参数随工程保存。旧工程保留统一字号；将最大字号和递减改为 1.8%、0.3% 后，点击“重新生成标注”即可启用分档。

哥白尼、第谷、柏拉图等常见重要地形优先占位，着陆点开启后也参与优先排版；普通标签及其中心不得抢占这些位置。重要标签紧凑位置全部失败时，才有限扩大搜索距离、允许较长引线。不会自动覆盖用户手动拖动或隐藏的选择，仍遵循受光、直径、类别、画面范围和数量上限；重要目标彼此过密或与手动位置冲突时仍可能收起。仅更新标签布局，不重新配准。

新照片的标签数量上限为 **200**，约束最终显示数量。布局避让后会从其余候选补位；手动隐藏的条目不占名额。实际数量仍取决于视野、直径筛选、地名目录和避让空间。

候选先保留手动指定的地形，再结合照片中的投影大小、坑缘明暗变化及周围地表纹理排序；图片分区的软权重避免标签集中在少数区域。主地形优先于附属字母坑，直壁、月溪等目录地形也参与选择，继续使用短引线。直径的权重会饱和，避免大而模糊的地形总是挤掉较小而清楚的坑。这是目录候选的显示排序，不是新增的环形山识别或定位结果。补位按需创建图形，碰撞检查只查询附近对象；达到显示上限即停止。 碰撞索引按标签尺度划分网格，已与文字冲突的位置提前退出，减少无效的中心与引线查询；不降低避让标准或标签数量。

“只标注照片中可见的受光地形”检查照片中的坑体与坑缘亮度，不再仅按日期计算的球面坑中心受光状态删掉标签。它保留亮坑缘和暗坑底，过滤黑暗区域；这是一项图像明暗启发式，不恢复真实地形光照，也不替代拍摄日期对几何投影的影响。没有照片的独立目录调用仍使用星历受光判断。

直径至少 35 km 且在照片中足够大的环形山可显示细的坑缘圈；小坑继续用中心点与短引线。“排版选项 → 轮廓形状”默认使用平滑 **椭圆**，可选 **坑缘轮廓（手绘风）**，点击“重新生成标注”应用。局部坑群识别优先在 LOLA DEM 中沿目录范围附近的连续坑缘高地取点，考虑地形高度投影，再拟合椭圆；坑缘轮廓选项保留这些点的不规则形状。平坦、未能解析的地形及其他识别路径仍使用目录参考圈。形状选项与高程轮廓保存在工程中，重新打开及导出无需再读取 DEM。大坑引线从轮廓边缘开始，避免横穿坑内。PNG 与 SVG 使用相同的轮廓和引线端点。基础 DEM 网格约 1.9 km，轮廓仍可能偏离照片中的细小或不规则坑壁；没有声称逐像素拟合精度。

确实排不下的标签会暂时收起，列表中显示“避让收起”。取消再勾选可优先显示，或减少其他标签。

名称与坐标来自 USGS / IAU。中文译名优先采用樊仕达（10deg）提供的 [LPND 月球与行星地名库](https://lpnd.bao.ac.cn/#/search?is=1) 资料快照：共 **9,040 条**，其中 **9,031 条标为 LPND 来源、9 条为其他来源补录**。结合缺失条目的旧词表兜底和主坑译名派生，当前 9,087 个地名中有 **9,042 个**可显示中文。旧 NADC 译名保留为搜索别名；冲突时显示 LPND 译名，不把全部补录归入 LPND。原始数据保存在 `moonlabeler/data/lunar_chinese_names.json`，来源与处理说明见同目录 `lunar_chinese_names.provenance.json`。本次核验了本地结构和目录匹配，未逐条在线复核全部 LPND 地名。

卫星坑标签统一使用“哥白尼 D”“哈得来 C”等简写，原始全称保留供检索与追溯。文件部分 LPND 条目仍带旧 NADC 链接，程序将其主来源指向 LPND，原链接只作为历史记录。旧离线 USGS 缓存加载时即可应用新译名，无需重新下载目录；没有译名的条目继续显示英文。搜索忽略拉丁字母变音符，例如 `Vaisala` 可找到 `Väisälä`。

## 离线局部模拟图

在“参考 → DEM 模拟”中：

1. 导入 LOLA 柱面 DEM 的 `.LBL` 或 `.IMG` 文件（两个文件必须放在同一目录）。也可点击“下载基础 LOLA DEM”，下载约 33 MB 的 `LDEM_16`。已有缓存不会重复下载。
2. 搜索照片中的已知区域，例如 `Aristarchus`，设置投影面上的视野宽度、图像边长、光照模型和 Gamma。
3. 点击“生成并预览局部模拟图”。程序根据当前拍摄时刻、地点、地形坡度及太阳方向生成参考图；可选择计算近似地形投影。
4. 可保存 PNG 和对应的 `.moonlabel` 参考工程，或尝试匹配当前照片。已有参考点会保留；与至少三处有效参考点明显不一致的匹配会被拒绝。

基础数据 `LDEM_16` 的赤道采样约为 **1.895 km**。这适合了解区域和验证流程；高倍照片、小型环形山、蛇谷细节需要更高分辨率的本地数据。增加输出像素不会增加地形细节。

支持的数据格式：

- LOLA 的 16 位有符号整数、东经为正、无网格旋转、DE421 平均地球/极轴坐标系的柱面 PDS3 IMG/LBL 数据。使用内存映射按需读取，避免把大型数据整幅载入内存。不支持极区立体投影或其他坐标系。
- 自定义 NPZ：`height_km` 为二维高度数组，单位 km，相对 1737.4 km 参考球面；`north`、`west` 为网格外边界经纬度，`pixels_per_degree` 为每度像素数。行从北到南、列向东，采用像素中心配准。缺测高度用 NaN。

实际 LOLA 模拟示例为 `examples/lola-aristarchus.moonlabel`。原来的 `examples/demo.moonlabel` 是合成校准示例，不能作为实拍识别准确性的证据。

## 模型边界

当前标注和模拟使用有限观测距离的**球面投影**。整月盘纹理参考使用 LROC 反照率图和球面光照，没有细致地形阴影。单独的 DEM 工具加入坡度法线、Lambert 或 Lommel–Seeliger 光照及地形遮挡采样，尚未与反照率纹理合成；没有完整起伏表面的视线求交或大气折射。手动局部模拟工具会拒绝明显接近月缘的中心；自动后备使用全月球面参考另行验证极区匹配，同样不含完整地形视线遮挡。

手动模拟的阴影追踪用 32 个距离样本，自动后备用 12 个，最大追踪 80 km；狭窄或更远的遮挡可能遗漏。区域 DEM 边界之外的数据不参与遮挡判断。光照和真实照片的差异会影响自动匹配，DEM 自动匹配属于辅助工具，仍需核对已知地形。

逐点偏差和自动匹配残差表示模型内的一致性，不能直接当作月面绝对定位精度。错认地形、错误时间、相机畸变及局部高差仍会造成误差。

NASA 在线参考保留在“参考 → 影像匹配”中，当前仅支持 2026 年及地心视角。SVS 的网络连接与 APOD 独立；在线下载失败不会阻止地形点校准和已有本地数据的使用。

### WinJUPOS 文件名时间

例如 `2026-08-31-2137_7-Moon_lapl3_ap311(1).tif` 自动填入 **2026-08-31 21:37:42 UTC**。`_7` 表示 0.7 分钟，即 42 秒。也支持标准的小数点形式 `2137.7` 和无分隔符形式 `21377`，允许拍摄者前缀及处理后缀。导入后状态栏和“具体时间”显示完整秒值，用户可修改时间；加载工程使用工程中已保存的时间。无效或不完整文件名不会覆盖当前时间。规范来自 [WinJUPOS 官方安装包](https://jupos.org/gh/download.htm)内英文帮助 *Image measurement → Image → WinJUPOS-Conventions*。文件名本身不能验证采集软件的时区配置，若原软件用本地时间命名，需要换算。

高倍照片的大坑可通过低分辨率长弧拟合产生椭圆候选，再用多个方向上的边缘验证。大半径搜索会降低工作分辨率，减少计算。候选可能受坑壁和阴影影响，请核对中心；单个候选不能独立证明地名或配准。

### 跨平台 GPU 与计算设置（0.7.0）

在项目目录激活虚拟环境后运行 `python -m pip install ".[gpu]"`，安装可选 wgpu 组件。macOS 使用 Metal，Windows 可使用 DirectX 12 或 Vulkan，Linux 使用 Vulkan；具体要求见 [wgpu 安装说明](https://wgpu-py.readthedocs.io/en/stable/start.html)。已在 Apple M5 Pro 实测；NVIDIA / AMD / Intel 尚待对应机器验证。无需安装 CUDA 或浏览器。Apple M 系列、支持 Metal 的 Intel / AMD Mac，以及支持所需 Vulkan / DirectX 12 计算功能的 NVIDIA / AMD / Intel 独显或核显均可尝试；品牌或系列名称不等于兼容保证，完整说明见 [README 显卡范围](README.md)。软件模拟显卡不作为 GPU 加速设备。

顶部“计算设置”提供“自动选择”“仅 CPU”，显示可用设备。选择“仅 CPU”可关闭 GPU；保存后下次计算生效，重启仍保留。偏好保存在本机缓存目录 `preferences.ini`，不随 `.moonlabel` 工程传递。显式设置的 `MOONLABELER_COMPUTE=cpu` / `auto` 优先于界面，旧 `metal` 值兼容为自动选择。

自动识别仅将高程与阴影参考计算交给 GPU；精确投影、纹理匹配、配准精修与标注继续使用 CPU。采样保留高程格内小数位置，灰度取整、阴影临界像素由 CPU 复核，另做分布抽样检查。首次执行包含内核编译。GPU 不可用、内存不足、计算失败或检查不符时回退，不要求用户更换显卡。小参考图和超过 GPU 缓冲预算的 DEM 继续使用 CPU。

旧版可选 `.[apple-gpu]` 安装仍可使用 MLX / Metal 作为 Apple 兼容后端；新安装建议统一使用 `.[gpu]`。未安装 GPU 组件也不影响功能。这不是神经网络识别，不需要训练模型。
